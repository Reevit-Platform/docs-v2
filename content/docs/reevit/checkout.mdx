# Checkout

Reevit Checkout provides a hosted, PCI-friendly payment experience you can launch from your app. Configure allowed origins, enable providers, and embed the checkout SDK for a full end-to-end flow.

---

## Choose Your Checkout Path

- **Server-created Checkout Session (Recommended)**: Create a checkout session on your backend, then pass `sessionSecret` to the React, Vue, or Svelte SDK.
- **Frontend-only Checkout SDK**: Embed a modal checkout experience directly in your frontend with a public key, amount, and currency. This remains supported, especially for sandbox/testing.
- **Payment Links**: Share a hosted checkout page with no frontend code.

<Callout type="info">
Payment Links are best for one-off sales or invoices. The Checkout SDK is ideal when you want a fully embedded experience.
</Callout>

---

## Prerequisites

1. **Connect a provider** in [Connections](/docs/reevit/connections).
2. **Grab your public key** (`pfk_test_...secret` or `pfk_live_...secret`) from **Developers → API Keys**.
3. **Decide your environment** (test vs live) and use the matching key.

---

## Step 1: Configure Checkout Settings

Open **Dashboard → Checkout Settings** and configure:

### Allowed Origins (Required)

Browser requests to the checkout endpoints are protected by CORS. Add every web domain that will open the checkout.

- Add **one origin per line**
- Include the **scheme** and **port** if needed (e.g., `http://localhost:3000`)
- Wildcards are supported for subdomains (e.g., `https://*.example.com`)

Example:
```
https://shop.example.com
https://checkout.example.com
http://localhost:3000
```

### Enabled Providers

Select at least one PSP so checkout can route payment intents. If none are enabled, checkout cannot initialize.

### Branding (Optional)

Set primary color and styling defaults so the checkout modal matches your brand.

### Update Allowed Origins via API (Optional)

```bash
curl -X PUT https://api.reevit.io/v1/checkout/settings \
  -H "X-Reevit-Key: pfk_live_xxx.secret" \
  -H "X-Org-Id: org_123" \
  -H "Idempotency-Key: checkout-settings-123" \
  -H "Content-Type: application/json" \
  -d '{
    "allowed_origins": [
      "https://shop.example.com",
      "https://checkout.example.com"
    ]
  }'
```

## Step 2: Create a Checkout Session

Create the payment on your backend with a private API key. This keeps payment creation, routing policy, metadata, and idempotency under your control.

```typescript
import { Reevit } from "@reevit/node";

const reevit = new Reevit(process.env.REEVIT_API_KEY!, process.env.REEVIT_ORG_ID!);

export async function createCheckoutSession(order: { id: string; amount: number; email: string }) {
  return reevit.checkoutSessions.create(
    {
      amount: order.amount,
      currency: "GHS",
      country: "GH",
      customer_id: order.email,
      metadata: { order_id: order.id },
    },
    { idempotencyKey: `order_${order.id}` }
  );
}
```

Your backend returns `session.session_secret` to the frontend. Do not expose private API keys in the browser.

## Step 3: Open Checkout (React Example)

```bash
npm install @reevit/react
```

```tsx
import { ReevitCheckout } from "@reevit/react";
import "@reevit/react/styles.css";

export function CheckoutButton({ sessionSecret }: { sessionSecret: string }) {
  return (
    <ReevitCheckout
      sessionSecret={sessionSecret}
      paymentMethods={['card', 'mobile_money']}
      email="customer@example.com"
      phone="0241234567"
      onSuccess={(result) => {
        console.log("Payment success", result);
      }}
      onError={(error) => {
        console.error("Payment failed", error.message);
      }}
      onClose={() => {
        console.log("Checkout closed");
      }}
    >
      <button>Pay GHS 100.00</button>
    </ReevitCheckout>
  );
}
```

On **Make payment**, the SDK submits the shopper's final method and provider
through the session-authenticated API. Reevit creates or reuses an intent scoped
to that checkout session, method, and provider, and the SDK opens the PSP only
after receiving the new intent. This is especially important for Paystack:
`resumeTransaction()` reopens the transaction represented by its access code,
so a Mobile Money selection must use a Mobile Money-specific access code.

The session secret authorizes this browser operation. Your private Reevit API
key stays on the server.

For Vue and Svelte, pass the same `sessionSecret` prop to `ReevitCheckout`. If you cannot add a backend yet, the frontend-only `publicKey + amount + currency` flow still works. Live frontend-created intents log a deprecation warning and should be migrated to checkout sessions over time.

## Option: Generate Checkout Integration with the Reevit CLI

Install the published CLI from npm, then scaffold and wire checkout into an existing frontend page:

```bash
npm install -g @reevit/cli@0.7.1
reevit init --goal checkout \
  --checkout-page src/app/cart/page.tsx \
  --checkout-fields price,name,email,phone,reference \
  --checkout-metadata order_id,product_sku
```

The published CLI is [listed on npm](https://www.npmjs.com/package/@reevit/cli) and its [source and binary release are on GitHub](https://github.com/Reevit-Platform/cli/releases/tag/v0.7.1). Local release candidates are not published versions.

In interactive mode, the CLI asks for:

- Which existing page should host the checkout button.
- Which customer fields to collect (`price`/`amount`, `name`, `email`, `phone`, `reference`).
- Which custom metadata keys to include (for example, `order_id` or `cart_id`).

Enter `-` at the page prompt (or pass `--checkout-page -`) to keep the scaffolded
component and runnable demo standalone. Customer values map to
`customer_name`, `customer_email`, and `customer_phone` workflow variables;
custom keys become `metadata_<key>`.

## Step 4: Handle Webhooks

To fulfill orders reliably, set up outbound webhooks.

- Configure your webhook endpoint in **Dashboard → Webhooks**.
- Verify signatures, then update your order state on `payment.updated` when
  `data.status` is `succeeded` — there is no `payment.succeeded` webhook.

If you create payments via SDK or API, Reevit injects the correlation metadata needed for PSP webhook routing automatically. Use `metadata` for your own fields. See [Webhooks](/docs/reevit/webhooks).

## Testing & Go Live

### Test Mode

- Use `pfk_test_...secret` keys for sandbox payments.
- Confirm flows end-to-end before switching to live keys.
- Learn more in [Sandbox & Test Mode](/docs/reevit/test-mode).

### Go Live Checklist

1. Switch to `pfk_live_...secret` keys.
2. Add your production domains to **Allowed Origins**.
3. Ensure live PSP connections are enabled.
4. Update webhook signing secrets in production.

---

## Troubleshooting

### CORS / network_error

If you see checkout requests fail in the browser:

1. Confirm the site origin is listed in **Checkout Settings → Allowed Origins**.
2. Ensure the origin includes scheme and port (e.g., `http://localhost:3000`).
3. Verify you are using a valid public key.

### Styles Not Loading

Make sure you import the SDK styles:

```tsx
import "@reevit/react/styles.css";
```
